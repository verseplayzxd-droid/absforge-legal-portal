# AGENTS.md

## ROLE
You are an expert Android engineer building a production-ready fitness app.
You write clean, simple, maintainable code.
You prioritize stability, clear UI behavior, and premium mobile UX over unnecessary abstraction.
You must preserve working features unless explicitly asked to change them.

---

## PROJECT OVERVIEW
This project is **AbsForge – 30 Day Abs Workout**.

It is a premium-looking Android fitness app focused on:
- a 30-day abs workout challenge
- beginner / intermediate / advanced workout plans
- quick workouts
- workout tracking
- streaks
- reminders
- progress analytics
- monetization with ads
- legal screens such as Privacy Policy and Terms of Service

The goal is to make the app feel polished and premium like top fitness apps, not like a prototype.

---

## PRIMARY GOALS
1. Build a stable Android fitness app.
2. Make the UI feel premium and modern.
3. Ensure workout flow works correctly from start to finish.
4. Use real and reliable exercise animations.
5. Keep data empty for first-time users unless real history is generated by usage.
6. Integrate ads correctly without breaking UX.
7. Avoid fake/demo behavior in release builds.

---

## TECH STACK
Use this stack unless explicitly told otherwise:

- **Language:** Kotlin
- **UI:** Jetpack Compose
- **Architecture:** MVVM
- **Navigation:** Navigation Compose
- **State management:** ViewModel + StateFlow / MutableStateFlow
- **Local persistence:** DataStore and/or Room
- **Reminders / notifications:** WorkManager or AlarmManager as appropriate
- **Media / sound:** Android audio APIs for sound effects and voice cues
- **Ads:** AdMob or Start.io depending on current task
- **Dependency injection:** only if needed; prefer simplicity
- **Do not add unnecessary new libraries without approval**

## CORE PRODUCT RULES
- First-time users must see clean empty/default states.
- Do not pre-fill fake workout history, streaks, achievements, weekly charts, or user stats unless the user has actually completed workouts.
- If no workout is completed:
  - streak = 0
  - workouts = 0
  - minutes = 0
  - calories = 0
  - charts should be empty or show a clean empty state
- Day completion must be based on actual completion logic, not static UI.

## WORKOUT PROGRAM RULES
The app contains:
- 30-day challenge
- multiple difficulty levels such as beginner, intermediate, advanced
- quick workouts
- individual exercise sessions
- rest/break periods between exercises

### Workout flow rules
- Starting a workout should open the proper workout session screen.
- Each day should contain a realistic number of exercises, not just 2 unless intentionally defined.
- Beginner days may have 4–6 exercises.
- Intermediate and advanced may contain more.
- Day completion must update progress properly.
- Once a day is completed:
  - mark that day as completed
  - update stats
  - update streak logic correctly
  - reflect completion on the home/progress screens

## EXERCISE ANIMATION RULES
This is extremely important.

### Main requirement
**Do NOT use a crude, glitchy, broken stickman animation system.**

The current poor-quality stickman animation must be replaced or improved significantly.

### Animation quality rules
- Exercise visuals must look clean, polished, and premium.
- Prefer high-quality 2D animated exercise visuals, vector human movement, or professional silhouette/anatomy-style motion.
- The result should feel similar to premium workout apps, not like a rough placeholder.
- Motion must be smooth and readable.
- No distorted limbs, broken joints, or glitchy frame transitions.
- No randomly floating body parts.
- No frozen or barely moving animation pretending to be animated.

### Preferred animation direction
Use one of these styles:
1. clean 2D vector human workout animation
2. premium silhouette-style body animation
3. simplified anatomy-style motion graphics
4. professionally looped sprite/image-sequence exercise animation

### Avoid
- ugly primitive stickman
- low-frame broken movement
- misaligned limbs
- inconsistent scale between exercises
- one generic animation reused for all exercises

### Exercise-specific behavior
Each exercise should have its own proper animation or motion asset.
Examples:
- crunch
- plank
- russian twist
- flutter kicks
- reverse crunch
- mountain climber
- leg raise
- bicycle crunch

Each animation must match the actual exercise.

### Timed vs rep-based exercise rules
- **Timed exercise:** show timer immediately from the first second
- **Rep-based exercise:** show rep target clearly
- Animation must still play during both types
- User must understand what to do by looking at screen

### If animation assets are missing
- do not fake a broken animation
- use a high-quality static exercise illustration as fallback
- or ask for approval before introducing a new asset system

## WORKOUT SCREEN RULES
Workout screen must be clean and logical.

### Must include
- current exercise index (e.g. 1 of 11)
- workout timer
- animated exercise preview
- exercise name
- exercise category / target area
- instruction text
- reps or countdown timer
- pause control
- close/exit control

### Important behavior rules
- Do not show a wrong CTA like a big static “DONE” button during active exercise if the exercise is still running.
- For timed exercises:
  - show proper running countdown
  - button logic must match actual state
- For rep-based exercises:
  - allow user to continue only when the exercise is completed or manually confirmed
- If an exercise finishes:
  - show a clean completion modal/screen
  - show **Retry** and **Continue**
- After the user continues:
  - show the break/rest screen
  - then move to the next exercise

### Break screen rules
- Break must be a separate and clear state
- Show 20s / 30s rest timer properly
- Include:
  - rest timer
  - next exercise preview
  - skip option if desired
  - continue logic
- Do not confuse exercise timer with break timer
